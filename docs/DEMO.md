# Freedom Lens — сценарий до 5 минут

Показываем существующий диалог организаторов и C01–C08, затем изменённый критерий.
Настоящая защита с Groq возможна **только после разрешения внешней передачи** и проверки
качества Нуртасом. Сейчас live quality — NOT TESTED. Offline provider ниже служит только
локальной технической репетиции: его объяснения, оценки и diagnostics нельзя выдавать за LLM.

## Подготовка вне пяти минут

1. Выполнить [Quick Start](../README.md). Импортировать выданный набор через UI, проверить
   группу/количество и выбрать `chat-quality / v1`. Для настоящего inference подготовить
   приватный grant по README после фактического согласования передачи/бюджета; обе службы
   используют один grant и показывают совпадающие admission protocol/hash/provider/model.
2. До разрешения передачи репетировать только изолированный offline HTTP-сценарий:

   ```bash
   ml-service/.venv/bin/python -B server/src/test/python/admission_dev_smoke.py \
     --dataset data/dev/invoke.json --ml-python "$PWD/ml-service/.venv/bin/python" --serve
   ```

   Harness поднимет настоящие Java/Python с временной SQLite и запрещённой внешней сетью.
   В напечатанном приватном workspace загрузить тот же `invoke.json` через «Данные».
   Выбрать один разрешённый чат: тестовый grant содержит5 RU,5 KZ,5 EN. Не использовать эти
   тестовые разрешения в обычном ML процессе. Enter завершает только тестовые процессы
   и удаляет временные данные. Browser regression запускать в отдельной свежей сессии.
3. Для живого показа сначала отдельно проверить один DEV-чат/v1, затем его v2, и только
   после проверки —15 разрешённых чатов (5 RU/5 KZ/5 EN). Нуртас сверяет с human review,
   включая C06/C07, смысл evidence, условия N/A, язык explanations, ошибки, реальные
   tokens/attempts/cost и время. Offline counts не являются этими измерениями.
4. Скрыть приватные пути, grant, ключи и signed URLs. Звонки показывать только локально:
   transcript/timestamps/audio control доступны, но звук не скачивать и не заявлять его анализ.

## Показ 4:50

| Время | Действие | Проверяемый результат |
|---|---|---|
| 0:00–0:35 | «Диалоги»: группа, RU/KZ/EN, открыть заранее выбранный допустимый чат. | Исходные роли, время и message IDs; полный список набора. Явно назвать реальный provider либо технический OFFLINE режим. |
| 0:35–1:45 | Выбрать C01–C08/v1, подтвердить рубрику, «Оценить с ИИ». | Реальные Java→Python HTTP, восемь ответов; итог/100 считает Java. При ошибке показать честную ошибку/ledger, без автоматического retry. |
| 1:45–2:15 | Открыть объяснение/evidence и перейти к реплике. Показать N/A, если оно применимо. | Цитата совпадает точно; N/A исключает только разрешённый вес; C08 отдельно от численного штрафа. Не придумывать N/A ради показа. |
| 2:15–2:50 | Апелляция по одному критерию → reviewer change с причиной и точным evidence. | Original сохранён, Final пересчитан Java, решение в истории. Учебную правку обозначить явно. |
| 2:50–3:20 | «Критерии»: заменить один ID/название/instruction валидного критерия, сохранить новую версию. | «Оценить по новой версии» возвращает к диалогу; новое подтверждение рубрики. Grant внутри scope не редактируется. |
| 3:20–4:30 | Оценить тот же диалог по v2. | Ответ включает новый критерий; старые v1/Original доступны неизменными. Provider задержка не должна маскироваться готовым тестовым ответом. |
| 4:30–4:50 | «Результаты → Массовая оценка»: группа, закреплённая версия, прогресс/pause/reload. | Один запрос за раз; запретные записи учтены, unknown не повторяется автоматически. Новый group_id готовится данными/конфигурацией без изменения исходников. |

Это бюджет сценария, не гарантия скорости Groq. Два inference могут занять до70 секунд
каждый на Java; для строгого тайминга после разрешённой предварительной проверки можно
показать сохранённые реальные результаты, прямо обозначив это. Не называть репетицию
проверкой качества, не обещать неизвестные quota/cost/latency. При409 перечитать состояние
и сохранить draft, не повторять мутацию автоматически.
